# ADR-002: 为什么使用微信云函数

## 状态

已采纳

## 背景

确定使用微信小程序后，需要决定后端架构方案。备选方案包括：

1. **微信云开发（云函数 + 云数据库）** — 微信原生 Serverless 方案
2. **自建后端服务器** — 传统 Node.js/Python 服务器 + 数据库
3. **第三方 BaaS** — LeanCloud、Firebase 等
4. **纯前端方案** — 仅使用本地存储，无后端

## 决策

使用微信云开发的云函数和云数据库作为后端方案。

## 理由

### 1. 零运维成本

- 无需购买和管理服务器
- 无需配置域名、SSL 证书
- 无需处理扩容和负载均衡
- 微信官方托管，自动伸缩

### 2. 与小程序深度集成

- 云函数天然支持微信鉴权，无需额外实现登录流程
- `wx.cloud.callFunction` 直接调用，无需 HTTP 封装
- 云数据库权限规则与小程序用户体系打通
- 文件上传/下载与云存储无缝对接

### 3. 开发效率高

- 云函数即写即部署，无需 CI/CD 流程
- 云数据库免建表，文档型数据库灵活适配需求变化
- 微信开发者工具提供一体化开发体验

### 4. 成本可控

- 免费额度对个人项目足够（云函数 40 万次/月、数据库 2GB）
- 按量计费，无流量时零成本
- 适合用户量有限的家庭级应用

## 否决方案分析

### 自建后端服务器

- 需要购买云服务器（最低 ~50 元/月）
- 需要处理运维、安全、备份等问题
- 需要实现微信登录鉴权逻辑
- 对个人开发者维护负担过重

### 第三方 BaaS

- 引入外部依赖，数据不在微信生态内
- LeanCloud 免费额度有限，超出需付费
- Firebase 在国内访问受限
- 增加鉴权复杂度

### 纯前端方案

- 无法实现家庭协作（数据无法同步）
- 无法推送通知
- 数据仅存于本地，换设备即丢失
- 不满足核心需求

## 后果

### 正面

- 开发和部署极其简单
- 运维成本为零
- 与小程序生态完美融合
- 适合个人开发者和小规模项目

### 负面

- 被绑定到微信云开发平台，迁移成本高
- 云函数冷启动可能造成首次请求延迟
- 云数据库查询能力不如 MongoDB 灵活（不支持复杂聚合）
- 调试不如本地服务器方便
- 免费额度有上限，超出需付费
