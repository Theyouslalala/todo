# ADR-001: 为什么选择微信小程序

## 状态

已采纳

## 背景

需要为三口之家开发一个共享提醒事项应用。备选方案包括：

1. **微信小程序** — 基于微信生态的轻量应用
2. **原生 App（iOS + Android）** — 独立移动应用
3. **Web App（PWA）** — 基于浏览器的渐进式 Web 应用
4. **企业微信/钉钉机器人** — 基于企业通讯工具

## 决策

选择微信小程序作为前端平台。

## 理由

### 1. 用户群体匹配

- 目标用户为 50 岁左右的父母，微信是他们日常使用的唯一通讯工具
- 无需额外安装 App，降低使用门槛
- 微信账号体系天然支持家庭成员身份

### 2. 开发成本低

- 单一代码库覆盖 iOS 和 Android
- 原生框架学习曲线平缓
- 微信开发者工具提供完整的模拟器和调试能力

### 3. 生态能力丰富

- **订阅消息**：无需自建推送服务，直接使用微信消息通道
- **云开发**：免服务器部署，内置数据库、云函数、存储
- **分享能力**：天然支持微信好友/群分享，便于邀请家庭成员

### 4. 适合项目规模

- 本项目为个人/家庭级应用，用户量有限
- 不需要应用商店审核流程
- 迭代速度快，适合快速原型开发

## 否决方案分析

### 原生 App

- 开发成本高（需维护 iOS + Android 两套代码）
- 50 岁用户安装独立 App 意愿低
- 需要服务器和后端基础设施

### Web App (PWA)

- 微信内置浏览器对 PWA 支持有限
- 无法使用微信订阅消息推送
- 离线能力受限

### 企业微信/钉钉机器人

- 交互形式受限（主要为消息卡片）
- 不适合复杂的待办管理 UI
- 家庭场景不适用企业工具

## 后果

### 正面

- 用户无需安装，扫码即用
- 开发和维护成本最低
- 微信生态提供推送、分享、支付等开箱即用能力

### 负面

- 受限于微信平台规则和审核
- 包大小限制（目前 2MB，分包最大 20MB）
- 无法在微信外使用
- 技术栈被绑定到微信生态
