# Family Reminder App - Design Specification

> 三口之家共享提醒事项小程序设计文档

## 1. 项目概述

### 1.1 项目目标

开发一个微信小程序，为三口之家（用户、爸爸、妈妈）提供共享提醒事项管理功能。支持农历日期、购物清单（整合为待办分类）、家庭成员协作，并预留AI功能扩展接口。所有待办事项均可设置提醒通知。

### 1.2 核心原则

- **功能完备但不复杂**：覆盖家庭日常需求，操作简洁直观
- **微信生态集成**：利用微信云开发，免运维，消息推送便捷
- **AI可选**：AI功能通过开关控制，关闭后核心功能完整运行
- **版本控制**：全程Git管理，最终上传GitHub

### 1.3 用户画像

- 用户（孩子）：技术使用者，负责创建和管理提醒
- 爸爸（50岁左右）：接收提醒，完成任务
- 妈妈（50岁左右）：接收提醒，完成任务，可能创建购物清单

### 2.3 数据库设计

#### 集合：users（用户）

```json
{
  "_id": "string",
  "openid": "string",
  "name": "string",
  "avatar": "string",
  "role": "string (child/father/mother)",
  "familyGroupId": "string",
  "settings": {
    "fontSize": "normal",
    "enableAI": false
  },
  "createdAt": "date"
}
```

#### 集合：reminders（提醒事项/待办）

统一的待办事项集合，购物清单作为"shopping"分类整合其中。所有待办均可设置提醒通知。

```json
{
  "_id": "string",
  "title": "string",
  "description": "string",
  "color": "string (red/blue/green/yellow)",
  "priority": "string (high/medium/low)",
  "category": "string (daily/shopping/family/bill/other)",
  "dueDate": "string (YYYY-MM-DD)",
  "dueTime": "string (HH:mm)",
  "isLunar": "boolean",
  "lunarDate": "string (如：五月初五)",
  "repeat": "string (none/daily/weekly/monthly/lunar_yearly)",
  "assignedTo": "string (userId)",
  "createdBy": "string (userId)",
  "familyGroupId": "string (所属家庭组)",
  "status": "string (pending/completed)",
  "images": "array",
  "quantity": "string (仅购物类：如2颗、3斤)",
  "enableNotification": "boolean (是否开启提醒推送)",
  "notifyBefore": "number (提前多少分钟提醒，默认15)",
  "createdAt": "date",
  "updatedAt": "date",
  "completedAt": "date",
  "deletedAt": "date (软删除标记)"
}
```

> **状态说明**：`pending`（待办）、`completed`（已完成/已购买）
>
> **软删除**：`deletedAt` 不为空表示已删除，不显示在列表中，30天后自动清理

#### 集合：activity_logs（操作日志）

记录家庭组内的操作历史，用于追溯谁在什么时间做了什么。

```json
{
  "_id": "string",
  "familyGroupId": "string",
  "userId": "string",
  "action": "string (create/complete/delete/update)",
  "targetTitle": "string (操作对象标题)",
  "detail": "string (操作详情)",
  "createdAt": "date"
}
```

#### 集合：notification_records（通知订阅记录）

跟踪每个用户的订阅消息剩余次数，确保推送不丢失。

```json
{
  "_id": "string",
  "userId": "string",
  "templateId": "string (模板ID)",
  "remainingCount": "number (剩余订阅次数)",
  "lastSubscribeAt": "date",
  "updatedAt": "date"
}
```

#### 集合：family_groups（家庭组）

```json
{
  "_id": "string",
  "name": "string",
  "members": "array (userId列表)",
  "inviteCode": "string",
  "createdAt": "date"
}
```

## 3. 功能设计

### 3.1 首页 - 今日待办

- 以卡片形式展示今日待办事项（含购物类）
- 每张卡片显示：标题、时间、颜色标签、负责人、分类图标
- 购物类事项额外显示：数量、勾选已购买按钮
- 支持左滑完成/删除操作（删除为软删除，可恢复）
- 右下角浮动按钮快速添加待办（快速模式：仅填标题+时间即可创建）
- 未读提醒数量角标
- 顶部分类筛选：全部 / 日常 / 购物 / 家庭 / 账单
- 顶部搜索栏：支持按标题搜索待办事项
- 下拉刷新 + 上拉加载更多（分页加载，每页20条）

### 3.2 日历页

- 月视图展示
- 自动显示农历日期
- 有事项的日期标记圆点（不同颜色代表不同分类）
- 点击日期查看当天事项列表
- 支持切换月份

### 3.3 我的页面

- 家庭成员管理（邀请码加入）
- 已完成事项回顾（含已购买商品历史）
- 操作日志（查看家庭组内谁做了什么）
- 回收站（查看/恢复已软删除的待办，30天后自动清理）
- 订阅次数管理（查看剩余次数，一键补充订阅）
- 设置页面：
  - AI功能开关
  - 字体大小调整
  - 通知偏好

### 3.4 待办创建流程（统一入口）

支持两种创建模式：

**快速模式（默认）**：最少操作即可创建
```
点击 ＋ 按钮 → 填写标题 → 选择时间 → 完成
（分类默认"日常"，负责人默认自己，通知默认开启）
```

**完整模式**：点击"更多选项"展开
```
选择分类 → 选择颜色标签 → 选择负责人
    ↓
设置重复 → 开启/关闭通知 → 设置提前提醒时间
    ↓
添加描述/图片（可选）→ 购物类可填数量
    ↓
选择农历/公历 → 保存
```

### 3.5 提醒通知机制

- 每个待办事项独立控制是否推送通知
- 创建时可设置提前提醒时间（默认15分钟，可选0/5/15/30/60分钟）
- 购物类事项支持"出门前提醒"（自定义时间）
- 使用微信订阅消息API推送
- 小程序内显示未读数量

**订阅消息策略（重要）**：

微信订阅消息为一次性授权，每点击一次"允许"获得一次发送机会。为确保通知不丢失：

1. **创建待办时自动请求订阅**：用户点击保存时，弹出订阅授权弹窗
2. **订阅次数追踪**：`notification_records` 集合记录每个用户的剩余订阅次数
3. **低次数提醒**：剩余次数 < 3 时，在首页提示"订阅次数不足，点击补充"
4. **批量订阅**：用户可在"我的"页面一次性补充订阅次数（最多连续订阅3次/模板）
5. **发送后扣减**：每次成功推送后，剩余次数 -1
6. **失败降级**：订阅次数不足时，仅显示小程序内通知（红点+未读数）

### 3.6 农历支持

- 日期选择器支持公历/农历切换
- 农历日期自动显示在日历上
- 支持农历每年重复（适用于祭祖、传统节日）
- 农历闰月处理：使用 lunar-javascript 库自动判断闰月，创建待办时可选择"闰五月"等
- 农历转公历：每年自动计算农历对应的公历日期，用于定时推送

### 3.7 通知系统

- 使用微信订阅消息API
- 用户首次授权后可接收推送
- 每个待办独立控制通知开关
- 提醒时间到达时自动推送给负责人
- 支持设置提前提醒（0/5/15/30/60分钟）
- 小程序内显示未读数量
- 订阅次数不足时降级为小程序内通知
- 操作日志记录通知发送结果

## 4. AI功能模块（可选）

### 4.1 开关控制

- 用户设置中的 `enableAI` 开关控制
- 关闭时：所有AI功能入口隐藏，核心功能正常运行
- 开启时：显示AI功能按钮，调用Python服务

### 4.2 语音识别

- 使用OpenAI Whisper模型
- 支持普通话（后续可扩展方言）
- 语音转文字后自动填充提醒标题

### 4.3 智能分类

- PyTorch文本分类模型
- 根据标题自动推荐分类和颜色标签
- 用户可手动覆盖

### 4.4 时间推荐

- 基于历史数据学习用户习惯
- 推荐最佳提醒时间
- 例如：用户总是在下午5点买菜，自动推荐

### 4.5 API接口

```
POST /api/ai/speech-to-text    # 语音转文字
POST /api/ai/classify          # 智能分类
POST /api/ai/recommend-time    # 时间推荐
GET  /api/ai/health            # 健康检查
```

## 9. 性能优化

### 9.1 数据库索引

为确保查询性能，需在云开发控制台创建以下索引：

| 集合 | 索引字段 | 用途 |
|------|----------|------|
| reminders | `familyGroupId + status + dueDate` | 按家庭组查询待办，按日期排序 |
| reminders | `familyGroupId + category + status` | 按分类筛选 |
| reminders | `assignedTo + status + dueDate` | 按负责人查询今日待办 |
| activity_logs | `familyGroupId + createdAt` | 按时间查询操作日志 |
| notification_records | `userId + templateId` | 查询用户订阅次数 |

### 9.2 数据加载策略

- **分页加载**：每次加载20条，上拉触底加载更多
- **缓存策略**：今日待办缓存到本地Storage，减少重复请求
- **图片压缩**：上传前压缩至800px宽，质量80%
- **增量更新**：使用 `updatedAt` 字段判断是否需要刷新

### 9.3 离线支持

- 使用 `wx.setStorage` 缓存最近查看的待办
- 离线状态下可查看已缓存的待办列表
- 离线创建的待办在联网后自动同步到云端

## 10. 约束与限制

- 微信小程序个人账号部分API受限（如微信支付）
- 订阅消息为一次性授权，需要用户主动点击订阅
- 云开发免费额度：5万次/月调用，2GB存储
- AI服务需要单独部署，不包含在微信云开发中
- 农历闰月处理需使用 lunar-javascript 库的闰月判断功能
- 图片上传单文件最大10MB，需前端压缩后上传
